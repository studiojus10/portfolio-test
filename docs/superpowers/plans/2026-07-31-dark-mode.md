# Dark Mode Token Layer Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the 35-rule `!important` dark-mode override sheet with a CSS-variable token layer that Tailwind reads from, so every page themes correctly without per-utility patches.

**Architecture:** Tailwind's colour palette is rewritten as `rgb(var(--c-NAME) / <alpha-value>)`. `:root` holds light channel triples; `html[data-theme="dark"]` reassigns only the tokens that differ. Utilities whose light value is shared but whose dark value must diverge (borders vs. text) get their own tokens. The always-dark footer bar gets theme-invariant tokens so it does not invert.

**Tech Stack:** Astro 7.1, Tailwind 3.4.19 (CJS config), Playwright (`npm test`), Prettier for `.astro`, Biome for `src/scripts`/`tests`/`*.js`.

## Global Constraints

- **Light mode must not change.** Every computed colour in light mode is identical before and after. This is asserted, not assumed.
- **Zero `!important` in the theme layer.** The only survivor is the nav's deliberate translucent-blur panel (`src/styles/site.css:63-94`), which is a visual effect, not a colour override.
- Channel triples are stored space-separated and unwrapped (`252 249 248`), never `rgb(...)`, so `<alpha-value>` compiles. `bg-surface/50` must keep working.
- Tailwind config is CommonJS (`module.exports`) — do not convert it to ESM.
- Run `npm run format` before committing; `.astro` is Prettier-formatted, `tests/` and `*.js` are Biome-formatted.
- The dev server may already be running on :4321. Playwright uses its own preview server on :4173 via `playwright.config.js`.
- Media lives in a mounted volume, so `/assets/*` 404s in tests are expected and must stay ignored.

```ts
import type { Page } from "@playwright/test";

/** Seed the persisted theme before any page script runs (pre-paint). */
export async function setTheme(page: Page, theme: "light" | "dark") {
  await page.addInitScript((t) => {
    localStorage.setItem("co-theme", t as string);
  }, theme);
}

/** Read a custom property off <html>. */
export function readVar(page: Page, name: string): Promise<string> {
  return page.evaluate(
    (n) =>
      getComputedStyle(document.documentElement).getPropertyValue(n).trim(),
    name,
  );
}

/** Computed colour of the first element matching `selector`. */
export function computed(
  page: Page,
  selector: string,
  prop: "backgroundColor" | "color" | "borderTopColor",
): Promise<string> {
  return page.evaluate(
    ([s, p]) => {
      const el = document.querySelector(s as string);
      if (!el) throw new Error(`no element for ${s}`);
      return getComputedStyle(el)[p as "color"];
    },
    [selector, prop],
  );
}
```

```js
// Fails when a template introduces a raw colour literal. Colour belongs in
// src/styles/tokens.css so both themes stay in step; the override sheet this
// replaced decayed precisely because literals bypassed it.
//
// Escape hatch: put `fixed:` in a comment on the same line for colours that
// are deliberately theme-invariant (brand red, scrims over photography).
import { globSync, readFileSync } from "node:fs";

const LITERAL = /#[0-9a-fA-F]{3,8}\b|rgba?\([\d\s,./%]+\)/;

// Tailwind arbitrary-value shadows (shadow-[0_2px_8px_rgba(0,0,0,.1)]) carry a
// literal that cannot be annotated: a class attribute has no comment syntax, so
// there is nowhere to put `fixed:`. They are theme-invariant decorative
// shadows, 44 of them across src/pages. Strip them before scanning rather than
// exempting whole lines, so a real offender sharing a line is still caught.
// Only shadows are stripped — bg-[#fff] and friends must still fail.
const SHADOW_ARBITRARY = /shadow-\[[^\]]*\]/g;
const offenders = [];

for (const file of globSync("src/**/*.astro")) {
  const lines = readFileSync(file, "utf8").split("\n");
  lines.forEach((rawLine, i) => {
    const line = rawLine.replace(SHADOW_ARBITRARY, "");
    if (!LITERAL.test(line)) return;
    if (/fixed:/.test(line)) return;
    offenders.push(`${file}:${i + 1}  ${rawLine.trim().slice(0, 100)}`);
  });
}

if (offenders.length) {
  console.error(
    `Raw colour literals found in ${offenders.length} place(s).\n` +
      "Move them into src/styles/tokens.css, or mark the line `fixed:` if the " +
      "colour is deliberately the same in both themes.\n\n" +
      offenders.join("\n"),
  );
  process.exit(1);
}
console.log("No unapproved raw colour literals.");
```

## Self-Review

**Spec coverage.** Every section of `2026-07-31-dark-mode-design.md` maps to a task: colour-as-variable-layer → Task 1; token table → Task 1; inverse-surface trap → Task 3; home gallery room → Task 6; OS preference → Task 5; Phase 3 audit → Task 7; regression guard → Task 8. The spec's "delete the 35 overrides" is Task 4.

**Deviation from the spec, deliberate.** The spec did not anticipate that `border-on-background` and `text-on-background` share one palette entry while needing opposite dark values, nor that `bg-white` is Tailwind's built-in and unreachable by any token. Task 2 was added to resolve both. The spec named the footer tokens `inverse-surface`/`inverse-on-surface`; those names are already taken in the palette by _different_ values (`#313030`, `#f3f0ef`), so using them would have shifted the footer in light mode and broken the "light mode unchanged" constraint. Task 3 uses `fixed-dark` plus the existing `surface-variant` instead, which reproduces today's footer exactly.

**Type/name consistency.** `--c-rule` / `border-rule`, `--c-rule-strong` / `border-rule-strong`, `--c-fixed-dark` / `bg-fixed-dark`, `--room-floor-far` / `--room-reflection` are used with identical spelling in every task that references them. Helper signatures `setTheme(page, theme)`, `readVar(page, name)`, `computed(page, selector, prop)` are defined once in Task 1 and used unchanged thereafter.

**Ordering constraint.** Task 3 must land before Task 4. The footer only survives today because `on-background` is absent from the override list; deleting that list first would invert all 39 footers.
